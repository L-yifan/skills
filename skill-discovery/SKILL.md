# Skill Discovery

README 是技能目录的唯一数据源。搜索时从 GitHub 实时拉取，不维护本地副本。

## 项目上下文预检（必须先执行）

在提取任务关键词前，先以**轻量、就近、有限**的方式了解当前工作区：

1. 从工作区根目录开始，检查根目录的 `AGENTS.md` 和 `CLAUDE.md`。
2. 若当前任务已指向工作区内某个子目录或文件，再沿该路径向上回溯至根目录，检查该路径链上的同名文件；根目录已读过的文件不重复读取。
3. 最多读取 3 个文件；每个文件最多读取前 12 KB（UTF-8）。不要递归遍历仓库、不要搜索其他说明文档、不要因寻找上下文而延迟技能推荐。
4. 将读到的内容压缩为少量推荐线索：技术栈、关键目录/模块、架构约束、常用命令和当前工作范围。路径越近的说明优先；同一事实冲突时，采用更近文件的规则。
5. 若根目录和任务路径链上均不存在 `AGENTS.md` / `CLAUDE.md`，立即询问用户“需要推荐什么能力或任务？”。此时不要扫描仓库来猜测项目，也不要执行 GitHub 技能目录搜索。

项目上下文只用于扩展关键词和重排候选，不能取代用户明确提出的任务意图，也不能据此臆测用户要做的事。

## 搜索流程

### 1. 提取与扩展关键词

先从用户任务中提取 2-5 个关键词（中英文 + 同义词）。若已完成项目上下文预检，再仅补充与任务直接相关的技术栈、模块或约束词；不要把整个项目的术语都加入搜索。构建 `grep -iE` 正则。示例：

- 用户说"管理笔记" → `grep -iE "obsidian|note|笔记|知识库|wiki"`  
- 用户说"审查代码" → `grep -iE "review|审查|代码|code.review|diff"`
- 用户说"处理 PDF" → `grep -iE "pdf|PDF|文档|document"`

### 2. 执行搜索

```bash
gh api repos/L-yifan/skills/contents/README.md --jq '.content' | base64 -d 2>/dev/null | grep -iE "<regex>" || echo "FALLBACK"
```

- 输出：匹配的 README 表格行，每行包含 `| 技能名 | 描述 | 来源 | 安装命令 |`
- 从匹配行中提取技能名、描述、安装命令

### 3. 降级路径

若 `gh` 不可用（未安装、未登录、网络问题），按优先级降级：

1. **优先**：用 `WebFetch` 读取 `https://raw.githubusercontent.com/L-yifan/skills/main/README.md`，在返回的 markdown 中搜索关键词
2. **兜底**：用 `WebSearch` 搜索 `site:github.com SKILL.md <user task keywords>`

### 4. 排名

对匹配行，以自然语言判定匹配度：

1. 关键词在**技能名**中出现 → 权重最高
2. 关键词在**描述**中出现 → 权重中等  
3. 关键词在**分类标题**中出现 → 权重较低
4. 同分类下自建技能优先
5. 在前四项相近时，优先与项目上下文中的技术栈、当前模块和约束直接匹配的技能

返回 ≤3 个候选，按匹配度降序。

## 输出格式

一句话结论，然后表格。安装命令必须完整可复制：

```markdown
| 推荐 | 技能 | 匹配原因 | 安装命令 |
|------|------|----------|----------|
| ★ 最推荐 | skill-name | 一句话 | `npx skills add ...` |
| ☆ 备选 | skill-name | 一句话 | `npx skills add ...` |
```

目录无匹配时说清楚，并建议扩大搜索范围或自建技能。
