# Skill Discovery

以 `L-yifan/skills` 远端 README 为唯一推荐数据源。每次检索读取当前版本，不维护本地副本。

## Workflow

### Step 1：确定检索意图

从用户请求提取 2–5 个任务词（可含中英文同义词）。只有当请求已经指向工作区内的文件或目录时，才轻量读取其路径链上的 `AGENTS.md` / `CLAUDE.md` 来补充直接相关的技术栈或约束：最多 3 个文件、每个最多前 12 KB、路径越近优先。

项目上下文只用于扩展关键词与重排候选，不能替代用户意图。若用户没有说明要解决的能力或任务，先询问该信息；否则直接检索，不因缺少项目说明而阻塞。

完成条件：得到一组能直接表达用户任务的检索词；仅在确有路径上下文时加入了相关约束词。

### Step 2：检索索引

按以下顺序读取 `L-yifan/skills` 的远端 README：

1. 优先使用 `gh` 查询仓库 README；解码其内容后读取完整表格。
2. 若 `gh` 因未登录、网络、TLS 或 API 错误失败，打开 `https://github.com/L-yifan/skills` 的仓库页并读取 README。
3. 仅当以上两种方式都失败时停止，并说明分别尝试的方法和失败原因。

只用 README 表格中的技能名、描述、分类、来源和安装命令匹配任务词。不得因索引暂时不可读而改用宽泛搜索，也不得将本机已安装技能、系统技能、推荐插件或其他仓库的技能当作索引候选。

只有用户明确要求扩大到索引外的公开技能时，才搜索 GitHub `SKILL.md`。这类结果必须单列为“索引外候选”，不得与个人索引候选混排、不得表述为已收录，也不得把未验证的安装命令写入结果。

若用户点名某个技能，先在 README 中按精确名称核验；命中时说明其分类、用途和原样安装命令，未命中时明确说明“当前索引未收录”，不要猜测名称或来源。

从每个匹配行保留技能名、描述、来源和 README 中原样记录的安装命令。

完成条件：已记录所有索引内直接匹配项，或已明确说明索引不可达；索引外候选仅在用户明确要求扩大范围时出现，并已清楚标识其来源边界。

### Step 3：排序并核验候选

按以下稳定顺序排序：

1. 技能名直接匹配任务词；
2. 描述直接回答用户任务；
3. 与当前任务的技术栈、模块或约束直接匹配；
4. 前三项相近时，优先同分类的自建技能。

最多保留 3 个候选。每个候选必须能给出一条具体匹配依据，并核验：名称、描述/分类、来源和安装命令均来自同一条 README 记录。安装命令仅可从 README 原样复制；没有可靠命令时标记“未验证，暂不提供安装命令”。

完成条件：每个候选都有可追溯的来源、匹配依据和已验证的安装命令或明确的缺失标记。

### Step 4：交付推荐

先给一句结论，再按匹配度输出表格：

```markdown
| 推荐 | 技能 | 匹配原因 | 来源 | 安装命令 |
|------|------|----------|------|----------|
| ★ 最推荐 | skill-name | 一句话 | README 分类或上游仓库 | `npx skills add ...` |
| ☆ 备选 | skill-name | 一句话 | README 分类或上游仓库 | `npx skills add ...` |
```

表格前说明使用的任务词与 README 获取方式（`gh` 或网页降级）。没有匹配时，说明已检索的范围和关键词，并建议用户明确授权扩大到索引外，或创建新技能。

完成条件：回复不超过 3 个候选；每个推荐均可由同一条索引记录和用户任务解释；没有可靠安装命令时未作猜测；未混入任何索引外或本机候选。
